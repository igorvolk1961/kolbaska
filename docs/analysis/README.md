# Артефакты системного аналитика

Набор аналитических артефактов по прототипу интернет-магазина колбасного цеха. Все диаграммы —
в формате Mermaid и отображаются на GitHub, в VS Code и других Mermaid-совместимых просмотрщиках.

## Состав

| Артефакт | Файл | Содержание |
| --- | --- | --- |
| Видение | [`vision.md`](vision.md) | проблема, цели бизнеса, vision statement, персоны, границы объёма, метрики, стейкхолдеры, риски |
| Требования | [`requirements.md`](requirements.md) | акторы, FR/NFR, пользовательские истории с критериями приёмки, матрица трассируемости, риски |
| Варианты использования | [`use-cases.md`](use-cases.md) | диаграмма Use Case, каталог сценариев, описания ключевых UC |
| Процессы | [`processes.md`](processes.md) | контекстная диаграмма (C4 L1), BPMN-схема заказа, sequence-диаграммы, жизненный цикл заказа |
| Глоссарий | [`glossary.md`](glossary.md) | термины предметной области, роли, технические понятия |
| Модель данных и API | [`../specification.md`](../specification.md) | спецификация, ER-диаграмма БД (Mermaid), реестр эндпоинтов |

## Как читать

1. **Видение** — зачем продукт, для кого и в каких границах (`vision.md`).
2. **Требования** — что система должна делать и как это проверяется (`requirements.md`).
3. **Варианты использования** — кто и зачем пользуется системой, пошаговые сценарии (`use-cases.md`).
4. **Процессы** — как именно протекают ключевые операции и как взаимодействуют компоненты
   (`processes.md`).
5. **Спецификация** — как это устроено технически: схема БД и API (`../specification.md`).
6. **Глоссарий** — общий язык для заказчика и команды (`glossary.md`).

## Трассируемость

Сквозная связь «требование → вариант использования → реализация → тест» приведена в разделе
«Матрица трассируемости» файла [`requirements.md`](requirements.md). Реализация — в
`backend/app/routers/*`, тесты — в `backend/tests/test_api.py`.
