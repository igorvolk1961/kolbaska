# Изображения товаров

Сюда кладутся реальные изображения изделий. Имя файла — **артикул (SKU) товара**, регистр не важен,
допустимы расширения `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`.

Примеры:

```
MS-001.png   # «Сон мясоеда» (Мясная лавка)
MS-002.webp  # «Любимой на завтрак»
AO-001.jpg   # «Колбасный авиалайнер» (Арт-объекты)
AO-016.png   # «Китобой «Фарш»»
```

Правила имени:

- берётся поле `sku` товара из `backend/app/content/catalog.py` (формат `MS-001`…`MS-016`, `AO-001`…`AO-016`);
- только артикул, без названия, пробелов и подкаталогов;
- расширение — одно из перечисленных.

## Оптимизация (важно)

Бэкенд предпочитает **WebP**: если рядом лежат `MS-001.png` и `MS-001.webp`, отдаётся WebP.
Оригиналы в git не попадают (см. `.gitignore`), коммитятся только лёгкие WebP.

Сжать исходники (png/jpg/jpeg) в WebP до 1200 px:

```
pip install -r backend/requirements-dev.txt
python backend/scripts/optimize_images.py
```

Скрипт создаёт `SKU.webp` рядом с оригиналом. Для повторной обработки добавьте `--force`.

## Как это работает

Бэкенд по адресам `/api/catalog/image/{SKU}` и `/api/catalog/placeholder/{SKU}.svg` сначала ищет
реальный файл в каталоге `IMAGES_DIR` (по умолчанию `images/products`), и если его нет — отдаёт
сгенерированный SVG-заглушку. Перезапуск и повторное сидирование БД не нужны: достаточно положить
файл.

В Docker каталог `images/` монтируется в контейнер как `/images`, поэтому положенные на хосте файлы
подхватываются автоматически (`docker compose -f docker-compose.yml up -d` перезапустит сервис).

## Где взять промпты

- Текст промптов для генерации: `docs/product-prompts.md` (по каждому SKU) или поле `image_prompt`
  в `backend/app/content/catalog.py`. Пересобрать документ: `python backend/scripts/export_prompts.py`.
- В интерфейсе технолога промпт показан на странице товара (блок «Промпт генерации изображения»).
